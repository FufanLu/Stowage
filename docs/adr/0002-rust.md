# ADR 0002: Rust as the implementation language

- Status: accepted
- Date: 2026-11-06

## Context

Database internals roles at large companies ask for C/C++ most often (Aurora,
AlloyDB, Redshift), followed by Java (Snowflake, Databricks, DynamoDB services).
Newer systems are increasingly written in Rust: TiKV, Neon, Databend, RisingWave,
Materialize, InfluxDB 3 and DataFusion. AWS wrote the core of Aurora DSQL in Kotlin
first and then rewrote it in Rust. JVM garbage-collection pauses dominated tail
latency at that scale, and the Rust version of the Adjudicator component reached
about 30k TPS where the tuned Kotlin version reached about 3k
([All Things Distributed, 2025](https://www.allthingsdistributed.com/2025/05/just-make-it-scale-an-aurora-dsql-story.html)).

## Decision

Write Stowage in Rust (edition 2024, toolchain pinned in `rust-toolchain.toml`).

- No GC, so tail latency is under our control. Benchmarks report p99 and p999, not
  just throughput.
- Ownership makes buffer-pool pin/unpin and latch lifetimes explicit in types (page
  guards). `loom` checks the remaining `unsafe`-adjacent concurrency.
- The ecosystem has the pieces we choose *not* to hand-write: `sqlparser`,
  `arrow-rs`, `pgwire`, `tonic`, `axum` and `rustls`. Effort goes into the parts
  that matter: the B+Tree, Raft, transactions, the optimizer and the executor.

## Consequences

- Compile times are long. A workspace split into crates and CI caching
  (`Swatinem/rust-cache`) keep iteration fast.
- `unsafe` is confined to page-layout code in `stowage-storage` and must carry
  `// SAFETY:` comments. `unsafe_op_in_unsafe_fn` is denied workspace-wide.
